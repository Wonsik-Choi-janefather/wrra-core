# WRRA Core 1.0

**A Domain-Agnostic Execution Architecture**

WRRA Core 1.0 is the frozen common execution grammar underlying the WRRA research program. It began in Minimal Computing Cosmology, but it is not limited to cosmology or physics. The Core defines how a system executes the present, reuses transport structures, renders observable phenotypes, preserves records, and separates structural explanation from empirical validation.

## Constitutional invariants

1. **Minimum Viable Computation** — use the minimally sufficient structure required to satisfy the declared viability or expression contract. Necessary reserve and redundancy are included in the minimum cost of survival.
2. **Common Carrier** — reuse one or a small number of transport/update structures across channels without erasing channel identity or ownership.
3. **Phenotype** — distinguish SOURCE and internal STATE from the observable output produced through a RENDERER and a BOUNDARY.

The Core also fixes the principles of **Fixed Present, Ownership, Boundary, Renderer, Record/Ledger, and Fail-Closed Claims**.

## Core execution sequence

```text
SOURCE → RELATION/LAW → STATE/RESIDUE → BOUNDARY
       → COMMON CARRIER → UPDATE → RENDERER → PHENOTYPE
       → OBSERVABLE/RECORD/LEDGER
```

Past effects operate only when they remain instantiated in the present as STATE, RESIDUE, or an accessible RECORD.

## Core and Domain Profiles

WRRA Core 1.0 contains no compulsory domain-specific equation, constant, dataset, prime-number ontology, string model, biological mechanism, neural architecture, price model, or cyclone model. Each application implements the Core as a separate **Domain Profile**.

Changes to WRRA-Physics, WRRA-Bio, WRRA-Cell, WRRA-AI, WRRA-Worm, WRRA-Econ, WRRA-Met, WRRA-Math, or WRRA-Method do not automatically revise Core 1.0. A Core revision is required only if a constitutional invariant or required execution element itself changes.

## Claim boundary

WRRA distinguishes five contracts:

- **Interpretation:** reconstruct a present or already recorded target.
- **Computation:** produce a next state from a complete current state and update rule.
- **Prediction:** reduce the loss or uncertainty of a future target using current information.
- **Control:** select actions that change future viability or objectives.
- **OPEN:** required information, error bounds, time, causality, or computational closure is missing.

Structural executability is not automatically presented as empirical validation. Domain Profiles must state their inputs, WRRA-specific transformation, outputs, and falsification conditions.
